# シンボク：改善提案「7年の拠点」への再構成

作成日：2026-09-12
前提：Build 18（`wireframe/`）と `docs/product-navigation.md` を現行仕様とする。
位置づけ：**提案であり決定ではない。** 実装・検証は未着手。ペルソナ（中3男子・受験期・「勝手にされるのが嫌い」）によるレビューを受けた再設計案。

---

## 0. 目的の再定義

> やりたいこと・好きなことから進路を逆算して、今後7年くらいの人生の中でどういうルートがあるのかを知り、**それを豊かにしていく拠点**。

この一文には、これまでの仕様書になかった要素が3つある。

| 要素 | これまでの仕様 | 再定義後 |
| --- | --- | --- |
| **7年という時間** | 分岐点として `#routes` に存在。ただし5画面のうち1つ | 製品の背骨。時間が主軸 |
| **拠点（= 何度も戻る場所）** | 「毎日使うことを必須にしない」とだけ書かれ、再訪の設計がない | 再訪の必然を構造で作る |
| **豊かにしていく（= 蓄積）** | 蓄積物はメモテキストのみ | 「やったこと」が7年の中に積まれる |

`product-navigation.md` が定義した中心は「領域を理解する地図」だった。これは**知るための道具**であって、**7年間いる場所**ではない。目的が変わった以上、中心を差し替える必要がある。

---

## 1. 現行構成が目的に届かない3つの理由

### 1-1. 時間軸が3タブ目に埋まっている

`#routes`（進み方を見る）は、すでに7年を表現している。

```
学問・研究   ← 大学2〜3年ごろ（専攻・研究室）
大学・学部   ← 高3の夏ごろ（学部・学科）
高校の中の選択 ← 高1の11月ごろ（文理・コース）
高校        ← 中3の12月ごろ（高校）
いま
```

これは **目的そのもの**である。しかし現在の既定の入口は `#personal`（自分のマップ）で、そこに時間軸は一切ない。

> 「今日決めなければならないのは、いちばん下の1つだけです」
> 「この経路は『今は決めない』という選択そのものです」

製品の価値がもっとも凝縮されたこの2文に到達するには、5タブのうち3番目を選び、8領域から1つ学問を選び、スクロールして最下部まで行く必要がある。**一番いいものが一番奥にある。**

### 1-2. 「逆算」の起点が、中学生が持っていないものになっている

現在の逆算は `学問を選ぶ → 経路4本` で始まる。だが対象者は学問名を持っていない。持っているのは「ゲームやってる」「料理する」「ギター弾く」である。

この断絶は `directions.mjs` が部分的に埋めているが、方向は topic 単位（ゲーム→誰かと楽しむ／自分でつくる／異分野）で、**興味の下位分類**にとどまる。ゲームの「つくる」と料理の「つくる」と音楽の「つくる」が、同じ場所に集まらない。

結果、「好きなことから逆算」の最初の1手が、実質「学問名をなんとなく選ぶ」になっている。

### 1-3. 蓄積が「メモ」しかなく、来るたびに増えない

拠点であるためには、来るたびに何かが増えていなければならない。現行の増分は、自分のマップの枝とメモテキストだけ。

メモは増えるが**豊かにはならない**。書いた本人が3か月後に読んで意味が復元できないテキストは、資産ではなく負債になる。しかも完璧主義寄りの対象者は、メモ欄の前で手が止まる（`product-design.md` 第2巡の自己批判「進路希望調査票のようになる」と同じ現象が、編集機能の積み増しで再発している）。

## 2. 提案：5画面を「7年の地図」1枚に畳む

### 2-1. 新しいホーム

起動して最初に見えるものを、**選択肢ではなく時間の構造**にする。

```
┌─────────────────────────────┐
│  大学2〜3年   専攻・研究室を選ぶ    まだ先        │  ← 折りたたみ
│  高3の夏     学部・学科を選ぶ      まだ先        │  ← 折りたたみ
│  高1の11月   文理・コースを選ぶ    まだ先        │
│  中3の12月   高校を選ぶ           あと3か月     │  ← 初期表示はここまで
├─────────────────────────────┤
│  いま（中3・9月）                              │
│   ・今週やったこと                              │
│   ・今できること                                │
└─────────────────────────────┘
```

**設計の要点**

- 学問を選ばなくても最初から見える。何も選んでいない状態の7年＝4つの分岐点と保留期限だけ。
- 初期表示は「今」＋2段。上2段は畳んでおき、展開して7年全体。
  （7年を一度に見せると圧迫になる。この折りたたみは検証必須。）
- 「今日決めるのは1つだけ」が、**起動直後の第一印象**になる。
- 下が「今」、上が未来。時間が上に伸びる既存の `#routes` の向きをそのまま使う。

### 2-2. 分岐点に「自分の現在地」を1行だけ置ける

各分岐点に、自分が今どう考えているかを1行だけ残せる。**空欄が正常。**

| 分岐点 | 例 |
| --- | --- |
| 中3の12月 高校を選ぶ | 「まだ決めてない」「普通科で考えてる」「高専も見てる」 |
| 高1の11月 文理を選ぶ | （空欄） |
| 高3の夏 学部を選ぶ | （空欄） |

空欄には「まだ決める段階ではありません」と表示する。既存仕様の「空欄は悪い評価ではなく『まだ記録していない』」を、時間軸に適用する。

**これが再訪の必然を作る。** 通知でもストリークでもなく、「次の分岐点が近づいてきた」というカレンダー的事実だけが、唯一の再訪理由として成立する。対象者は通知で動かない人物だが、期限が近づく事実からは逃げない。

### 2-3. 「いま」欄に、やったことが積まれる

拠点の蓄積物を、メモから**行動の記録**に変える。

- 今日やった15分の何か（生き物を1匹調べた／1曲弾けた／Scratchで1個動かした／味噌汁の味を変えてみた）を1行で置く
- 進捗管理ではない。締切なし、連続記録なし、達成率なし（`product-design.md` F23 の排除判断を維持）
- **ただ、過去の自分が何をしていたかが残る**

対象者の行動記録で最も重い事実は「一人だと続かない」（英語塾・縄跳び・筋トレ）である。続いたもの（ゲーム・料理・ギター）との差は意志ではなく、**やったら何かができあがるか**にある。料理は皿が出る。ギターは音が出る。縄跳びは何も出ない。

現行のシンボクは、読んで・眺めて・メモして終わる。対象者の分類では縄跳び側にいる。

蓄積の可視化は、ゲームの実績解除が続く理由と同じ構造で、かつ**本人しか見ない**。「勝手にされない」という中心的価値を一切壊さない。

副次効果として、7年後にこの記録は **総合型選抜・学校推薦型選抜で要求される「なぜこの道を選んだか」の材料**になる。これは本人にも保護者にも説明できる実利であり、サービスを続ける理由を外部から支えられる。

## 3. 提案：逆算の起点を「学問」から「動詞」に変える

### 3-1. 動詞を第一級の入口にする

学問名の代わりに、**やっていること・やりたいこと＝動詞**を起点にする。

| 動詞 | ゲーム | 料理 | ギター | 海・生き物 |
| --- | --- | --- | --- | --- |
| つくる | ステージを作る | 献立を組む | 曲を作る | 観察装置を作る |
| 分解する | 面白さの仕組みを分解 | レシピの工程を分解 | 音色が変わる要因を分解 | 生態系の関係を分解 |
| くらべる | 2作品の設計を比較 | 温度を変えて比較 | 弦・ピックで比較 | 2地点の生き物を比較 |
| 調べる | 制作の裏側を読む | 発酵の仕組みを読む | 楽器の構造を読む | 生息条件を調べる |
| つづける | 記録をつける | 毎週1品 | 練習ログ | 定点観察 |
| 伝える | 遊び方を説明する | 作って食べてもらう | 人前で弾く | 分かったことを書く |
| 直す | バグを直す | 失敗を作り直す | チューニング・調整 | 仮説を立て直す |

**なぜ動詞か**

1. **中3が既に持っている。** 学問名は持っていないが、「つくる」「分解する」は今日やっている。新しく何かを始める必要がない ＝ 三日坊主問題の入口が変わる。「新しいことを始めよう」ではなく「今やってることの先を見る」。
2. **領域を横断できる唯一の中学生語彙。** `product-navigation.md` R3 が求めた「方法を共有する」関係は、まさにこの動詞である。仕様が要求していたものを、対象者の言葉で実装することになる。
3. **学問にも高校の学科にも活動にも接続できる。** 「分解する」→ 生態学の野外調査、情報科学のリバースエンジニアリング、音響設計の測定。同じ動詞が複数の学問に着地する。
4. **「好きなこと」を1つの学問に固定しない**（旧仕様の明示的な要件）が、自然に守られる。

### 3-2. 動詞 → 7年の地図への接続

```
「つくる」が好き
   ↓ この動詞を仕事や研究にしている分野
   映像・ゲーム表現 / デザイン / 海洋工学 / 食品科学
   ↓ その分野への経路
   #routes の4経路（既存資産をそのまま使える）
```

既存の `routes.mjs`（8領域 × 4経路 = 32経路、保留期限、数学レベル）は**一切捨てずに済む**。手前に動詞の層を1枚足すだけで、対象者が持っていない「学問名」を要求しなくなる。

### 3-3. 実装コスト

- `knowledge.json` の `resources`（13件）と `topics`（8領域）に、動詞タグを付与する編集作業
- `directions`（12方向・36活動）を topic 単位から動詞単位に再編
- 動詞の定義は7個程度に抑える（増やすと分類作業になり、動詞の利点が消える）

これは新規開発ではなく、**データの張り替え**が主。

## 4. 捨てる提案

「枠をぶち壊してよい」との指示に対する、正面からの回答。

| 捨てるもの | 理由 | 影響ファイル |
| --- | --- | --- |
| `#personal` 自分のマップの自由編集 | 枝の作成・命名・関連理由の記述は、完璧主義寄りの対象者には作業。7年の地図に吸収 | `studio.mjs` `personal-map.mjs` `inquiry.mjs` `inquiry-ui.mjs` |
| `#map` 学びの地図（独立画面） | 8領域のグラフは、7年の地図の「学問・研究」段に統合できる。独立画面である必要がない | `app.js` の map ルート、`geometry.mjs` の一部 |
| `#saved` 気になる（独立画面） | 別置きにすると見に行かない。7年の地図の「いま」欄に統合 | `workspace.mjs` |
| 保護者共有のコード一式 | フラグを戻せば矛盾が再発する構造が残る限り、「共有機能はありません」と言い切れない。`self-evaluation.md` の次の改善5への回答 | `family-api.mjs` `family.js` `family.html` `family-api.test.mjs` `FAMILY_SHARING_ENABLED` |
| 5タブのボトムナビ | 2タブへ（**7年の地図** / **探す**） | `app.js` `styles.css` |

**捨てることで失うもの（正直な記録）**

- Build 07〜13 で作った招待・権限分離・Cookie・結合テスト15件は、実装としては妥当だった。捨てるのは品質の問題ではなく、対象者にとって**存在自体が不信の種**だから。
- 自分のマップの自由編集（Build 08〜11、undo・循環検査・40ノード検証）も同様。作りとしては動くが、対象者が使わない。
- 判断の記録を残すため、削除ではなく `archive/` への退避を推奨する。

## 5. データの方向転換

件数を増やす方向ではなく、**動詞 × 今できること**の格子を埋める。

### 5-1. 優先して作るもの

| 作るもの | 目標 | 理由 |
| --- | --- | --- |
| 今できること（自宅・無料・15分） | 7動詞 × 3件 = 21件 | 週500円・自宅完結・行動範囲が家と近所、という制約に直接合う |
| 動詞タグ | 既存13リソース全部 | 逆算の起点を成立させる前提 |

**現状の問題（レビューで確認）**：「ゲーム好き → 自分でつくる」で出てくるのが Scratch と CoderDojo。Z会タブレットで自由進度学習をこなす中3には幼く、離脱理由になる。料理を選んでも読みもの1件。**制約に合う「今日できること」が実質ゼロ。**

### 5-2. 地域の扱いを中間状態から抜け出す

現状は「地域を聞かない」方針を掲げつつ、都立高校の入試案内と大島海洋国際高校（伊豆大島・全寮制）が事実上のデフォルトになっている。これは「聞かない」ではなく「東京だと決めつけている」。

**提案**：高校段は学科の型のみとし、実在校名を出さない。都道府県の入試案内リンクだけを中立に置く。実在校を出すなら、地域指定を任意で受ける（初回に強制しない）。

### 5-3. 領域の偏りを表示する

8領域を等しく並べながら、中身は海に偏っている（大島海洋国際高校・同潜水部・学校説明会・東京海洋大3学部）。慎重な対象者は2〜3分で気づき、気づいた瞬間に他領域の記述も信用しなくなる。

**提案**：領域ごとの掲載件数を表示する。「この領域は掲載2件」と先に言うほうが、等量に見せて裏切るより信頼が残る。既存の「掲載情報なし／未調査／対象外を混同しない」方針の延長。

## 7. この提案自体のリスク

正直に記録する。

1. **7年を最初に見せると逆に重い可能性がある。** 「7年も先まで考えるのか」と感じた瞬間、対象者は閉じる。折りたたみの初期状態は検証必須で、外れたら「今＋1段」まで下げる。
2. **動詞7個への分類は、編集者側の作業が重い。** しかも分類の良し悪しを、本人観察なしで判定できない。動詞の粒度を外すと、いまの「学問8領域」と同じく本人が持っていない語彙になる。
3. **行動の記録が「宿題」に見えたら終わる。** F23 で排除した習慣化UIとの距離が近い。「やったことを書く欄」が空のまま並ぶと、それ自体が未完了タスクの一覧になる。空欄の見せ方が生命線。
4. **捨てる量が大きい。** Build 07〜13 の実装をほぼ全部退避することになる。技術的に間違っていたわけではなく、目的の再定義に合わなくなったという理由での退避である点を、記録として明示しておく。
5. **本人観察は依然ゼロ。** `self-evaluation.md` が挙げ続けている唯一の未達項目。この提案も、開発者とレビューの推論に基づく設計であり、実利用の観察ではない。**段階1を実装した時点で、一度観察を挟むべき。** 段階5まで作ってから観察すると、外したときの損失が大きすぎる。

---

## 8. 変えない部分

目的が変わっても、以下は維持する。これらは対象者の中心的行動原理（「自分について勝手に何かをされることを最も強く嫌う」）に直結している。

- 診断・適性判定・適合度スコア・順位づけを行わない
- 「あなたに向いています」を表示しない
- 登録・ログイン・必須入力なし
- 端末保存は既定オフ。同じブラウザを使う人から見える可能性を明示する
- 出典・確認日・「本アプリの編集である」ことの明記
- 特定の高校からの進学実績を主張しない
- 数学を適性ゲートにしない
- 経路に順位をつけない。4本を並列に出す（兄が高専にいる対象者にとって、これは特に重要）

## 9. 実装の記録（2026-09-12 追記）

この提案は Build 19 として実装した。実装内容と検証は `implementation-status.md`、評価は `self-evaluation.md` を参照。

### 提案どおりに実装したもの

| 提案 | 実装 |
| --- | --- |
| §2-1 `#routes` をホームに昇格 | `#now`。学問未選択でも4分岐点と保留期限が出る。初期表示は下2段 |
| §2-2 分岐点に1行の現在地 | 60字・任意。空欄には「まだ決める段階ではありません」 |
| §2-3 「いま」欄に行動の記録 | 日付＋1行。締切・連続記録・達成率なし |
| §3 動詞を逆算の起点に | 5動詞。既存36活動へのタグ付けで実装（新規作成ではない） |
| §4 捨てる提案 | 全件 `wireframe/archive/` へ退避。5画面→2タブ |
| §5-2 地域 | **未着手** |
| §5-3 領域の偏りを表示 | **未着手** |

### 提案から変えたこと

**動詞は7個ではなく5個にした。** 提案では「つくる／くらべる／観察する／調べる／伝える／直す／つづける」としていたが、既存36件の活動アイデアを分類したところ「直す」「つづける」がそれぞれ1件しか裏づけられなかった。

提案の §3-3 に「動詞の定義は7個程度に抑える（増やすと分類作業になり、動詞の利点が消える）」と書いた一方で、§5-1 では「7動詞 × 3件 = 21件」を目標にしていた。実際には、件数を満たすために活動を新規に作れば編集の裏づけがない活動が増える。そこで **「動詞ごとに活動3件以上」をデータ検証で強制し**、満たせない動詞を落とした。「直す」は「つくる」に、「つづける」は記録そのものに畳んである。

この判断は逆方向にも作用する。今後 `knowledge.json` に動詞を足しても、活動が3件揃うまで公開できない。

### 提案時に見落としていたこと

**掲載情報は13件ではなく42件あった。** レビューも提案も、UIの「現在は8領域・13件の公式情報を掲載」という表示を根拠にしていたが、これは Build 05 当時の文言が更新されないまま残っていたもので、実データは Build 17〜18 の調査で42件まで増えていた。
