# Service evaluation

## 評価の基準

対象は、ゲーム・料理・ギター・海の生き物が好きで、他人に相談する前に自分で試したい中高生。点数は開発者による操作検証の自己評価であり、本人によるユーザーテストの評価ではない。

合格基準は各軸4/5以上かつ合計24/30以上。未実装や未検証の動線を、他の項目の高得点で相殺しない。

- 1: 説明・固定例のみ
- 2: 一部の操作のみ可能
- 3: 主動線は動くが、重要な制約・未検証箇所が残る
- 4: 主動線と境界ケースを実装し、端末幅を含めて検証済み
- 5: 本人に近い対象者の利用観察でも妥当性を確認

## 次の改善

1. スマホの地図を、横に探し回らず興味の分岐と近領域が理解できる表示にする。選択中の文脈を保つ。
2. 本人／保護者の実際の共有に向け、招待と相手単位の閲覧権限・取り消しを実装する。モック内の表示制御をアクセス制御とみなさない。
3. 高校・校内活動・学外活動の掲載を補い、地域・費用・対象学年の条件を比較できるようにする。対象地域が不明な間は全国・オンラインから優先する。
4. 旧モック用データと説明の整理。旧保存データを壊さず、現行情報と混同しない表示へ移行する。
5. 実機と対象者の観察は未実施。開発者による操作確認と区別して記録する。

### Build 13までとの一番大きな違い

「保護者と共有できます」という表示が、対象者にとってこのサービスを使用不可能にする、という前提をコードに反映した。Build 07〜13では共有機能が実装され、気になるページの2番目のタブに置かれていた。現在は`FAMILY_SHARING_ENABLED = false`で導線ごと外れており、起動時に共有APIも呼ばない。

### 次の改善

1. 対象者本人（または近い条件の中学生）による利用観察。全軸で5に届かない理由はこれ1つである。
2. 利用者の地域を尋ねずに絞り込む方法の検討。現在は都道府県の入試案内へ送るところで止まっている。
3. 保留可能期限を、自治体の実際の入試日程と接続する。現在は一般的な目安。
4. 経路の「研究室」段を、実在の研究テーマまで降ろす。進学実績を主張しない範囲で。
5. 共有機能のコードを残すか撤去するかの決定。残す限り、フラグを戻せば矛盾が再発する。
