# シンボク：学びの領域を理解し、進路へつなぐ地図

更新日：2026-09-10

## プロダクトの中心

日常の興味から、何を学べるか・どんな問いや方法があるか・領域がどう重なるかを理解し、学校・課外活動・大学という具体的な選択肢につなげる地図。

意義は、別々の学校・活動・学問のページに散らばった内容を読み解き、本人が比較できる共通の言葉と関係に整理することにある。外部への誘導はその理解を深め、最新の条件を確認するための出口である。

設計原則は「扱う内容は広く、最初に見せる量は少なく、掘れば理解できる」。画面を軽くするために意味や根拠を薄くしない。

ユーザーが求めるのは「インターネット上の進学情報サイト以上の領域としての繋がり」である。機関やサイトをまたいで、課内・課外の経験、学問、方法、進み方をつなぐことを要件とする。既存サービスより情報量や機能が優れているという主張は、比較検証なしでは行わない。

最終目的は、本人が選択肢を理解し、自分の理由で進路を考えられること。今回の修正は目的の変更ではなく、そこに到達する手間を減らすものである。

本書を現時点の実装仕様とする。product-design.md は案出し・自己評価の記録として残す。旧仕様の「比較ノートを中心とする」「5つの画面を通す」構成は採用せず、主画面1枚と候補の詳細シートを中心にする。

## 設計上の優先順位

### 既存サービスと情報源の確認

- スタディサプリ進路には学問・仕事から探す入口がある。「既存の進学サイトには学問から探す方法がない」とは説明しない。[学問を調べる](https://shingakunet.com/gakumon/)、[サービスのトップページ](https://shingakunet.com/net/index)
- 東京海洋大学は、海洋を対象に生命科学・工学・資源環境などの学びを紹介している。ひとつの関心が複数分野に広がる具体的な情報源の一例である。[学部・研究科](https://www.kaiyodai.ac.jp/faculty/)
- 学校以外の学びを調べる情報源には、JSTの次世代科学技術チャレンジプログラムなどもある。個々の活動への参加条件・現在の募集は別途確認する。[事業公式サイト](https://www.jst.go.jp/cpse/stella/)

上記は代表例の確認であり、市場全体の機能調査ではない。差別化仮説は「高校から大学までの時間軸と、校内外・学問間の横の関係を、中学生が理解できる共通の観点でたどれること」とする。

### 優先する体験

1. 開いた瞬間に、何が見られるかがわかる。
2. 入力・登録・設定なしで、具体的な選択肢に触れられる。
3. アプリ内で領域の意味・違い・重なりを理解できる。
4. 理解した内容から、具体的な機会と深掘り先に進める。
5. 外から戻ったときに、どこを見ていたかがわかる。
6. 残したいときだけ、候補・感想・相談内容を残せる。

メモ、比較、相談を終えることを探索の条件にしない。

## 最初に開いた画面

### Build 04の入口と画面遷移

通常の入口は `#home`。興味の例と小さな樹形図で用途を説明し、1クリックで `#map` に進む。登録・診断・自由記述は不要。`#map` に直接アクセスする場合は入口を経由しない。

保存を本人が有効にしている場合、入口に前回の学び・気になる件数・再開ボタンを表示する。気になるものは `#saved`。3画面の間はブラウザの戻る／進むに対応する。詳細は地図に併設し、比較・相談はダイアログとして開く。

候補・メモ・探索位置の端末保存、復元、保存オフ、全削除を実装。初期値は保存オフで、同じブラウザを使う人から見える可能性を説明する。更新失敗・データ破損は無言で上書きせず表示する。

以下の初期案にあった「通常URLでも最初から地図」という導線は、上記の入口と地図への直接アクセスの併用に更新する。

- チュートリアル、アカウント登録、質問票、地域設定のモーダルで開始を遮らない。
- 初期版の対応分野を明示し、例として海・生き物の地図をすぐ表示する。「あなた向けに選びました」とは表示しない。
- 上部に興味の切替を少数置く。自由入力は追加の入口であり必須ではない。
- 地域は「地域を指定」で後から変更する。所在地を決めつけたり、位置情報の許可を最初に求めたりしない。
- 操作の主役は「地図を見る」「候補を開く」。大きなダッシュボードや未完了タスク一覧を置かない。

## 領域理解の機能要件

### R1：学びの領域を広く見渡す

- 学問名や学校種だけで分類せず、「何を対象にするか」「何を知りたい・実現したいか」「どんな方法を使うか」からたどれる。
- 自然・生き物、技術・ものづくり、表現・文化、人・社会、暮らし・健康などを初期の入口候補とする。正式な分類や網羅性を断定する一覧ではなく、調査して修正する。
- 同じ対象を複数の領域から見られるようにする。1つの興味を1つの学問に固定しない。
- 分野名だけを大量に並べず、各領域に説明と関連の意味を持たせる。

### R2：その領域で何をするかを理解する

領域を開くと、最初は短い説明を見せ、以下を任意に展開できる。

1. 何を扱う領域か。
2. 代表的な問いや取り組みの具体例。
3. 観察・実験・制作・調査・分析など、実際の取り組み方。
4. 学ぶ内容や使う知識。入試条件とは区別する。
5. 近い領域と重なる点・異なる点。
6. 学べる場所・試せる機会と、その関連理由。
7. 説明の出典と、さらに深く読む外部情報。

本人は外部ページを何枚も読まなくても、領域の大まかな意味と違いを説明できることを目指す。一文の要約だけに制限しない。

### R3：領域を横断する関係を理解する

- 関係は「同じ対象を扱う」「問いを共有する」「方法を共有する」「知識を応用する」「基礎になる」などに区別する。
- すべての線に「なぜつながるか」の説明を用意する。単なるタグ一致や検索結果への同時出現だけで関係を確定しない。
- 有向の関係と相互の関係を区別する。「関連」を一律の進行方向にしない。
- 「基礎になる」は有用な準備と必須の履修条件を区別し、不要な参入障壁を作らない。
- 最初は選択した領域の周辺だけ表示するが、さらにたどれることと他にも候補があることを示す。
- 異分野間の往復で、現在地とたどった経路を把握できるようにする。

### R4：学びの内容から具体的な機会へつなぐ

- 領域から高校・高専の授業、校内活動、学外活動、大学での学びへ切り替えられる。
- 候補との接続には「何を学べる・試せるため関連するのか」を記載する。
- 学校名・イベント名のキーワード一致だけでは接続しない。実際の授業・研究・活動内容を確認する。
- 領域同士の関連と、学校への進学資格・活動への参加資格を別の情報として扱う。
- 地域・年齢の指定は機会の絞り込みに使い、学問・領域の存在自体を非表示にしない。

### R5：違いを同じ観点で見比べる

- 近い2領域を「対象・問い・方法・学ぶこと・試せること」で比較できる。
- 片方に情報がない場合は未整備と示す。未知の内容を差分として断定しない。
- 比較を見る前に本人の価値観入力を要求しない。
- 自分の気になる点は任意で残せる。領域の順位や本人への適合度は算出しない。

## 網羅性の範囲と内容を作る要件

網羅性を「全国の全学校・全情報を収録すること」と同一視しない。次の3点を別々に確認する。

| 観点 | 確認すること |
| --- | --- |
| 領域の広がり | 自然科学など特定の系統だけに偏らず、探索対象の主要な領域が入口にあるか |
| 内容の深さ | 掲載した領域について、対象・問い・方法・学ぶこと・機会を理解できるか |
| 接続の広がり | 親子分類だけでなく、隣接・横断する領域への根拠のある接続があるか |

- 領域ごとの内容整備表を作り、説明・具体例・関係・出典・機会の有無を点検する。
- 「情報がない」「未調査」「対象外」「関連しない」を混同しない。
- 初期版は1つの興味を起点としつつ、複数の学び方と隣接領域を深くたどれる内容を整える。無関係な領域に接続して件数を満たさない。
- 他の領域も実際に探索できるようになるまでは、全領域を網羅すると表示しない。全国の学校・活動データは引き続き対象外でよい。
- 地域と開催条件の制限は実在の機会に適用し、内容の地図全体を1地域の学校情報に従属させない。

情報整備の手順：

1. 公式の学科説明・授業内容・研究紹介・活動案内などを、見出しだけでなく本文まで読む。
2. 記載内容を、対象・問い・方法・学ぶこと・参加条件などへ整理する。
3. 情報源に直接書かれた事実と、複数の情報を横断した編集上の解釈を区別する。
4. 接続に短い理由と根拠を付ける。推論でつないだ場合はその旨と限界を示す。
5. 意味や方向が妥当か、根拠が主張を支えているかを確認してから公開する。
6. 学校・活動の条件は年度や確認日を付け、説明内容と別に更新できるようにする。

AIを使う場合は情報の抽出・整理の下書きを支援する役割とする。出力だけを根拠に関係を確定せず、出典の該当内容を確認する。モデルがそれらしく補完した関係を、そのまま公式情報として表示しない。

### 関係を持つための情報モデル

ページのタイトルとURLだけを登録する方式ではなく、次の情報を共通の項目として持つ。

| 種類 | 保持する内容 |
| --- | --- |
| 興味・問い | 日常の表現、対象、知りたい・作りたい・変えたいこと |
| 学問・研究テーマ | 扱う問い、取り組み方、関連する知識 |
| 方法・技能 | 実際に行う作業や使う考え方。役立つ準備と必須条件を区別 |
| 学校・授業・活動 | 提供する学び・経験、機関との所属関係、実施条件 |
| 社会での関わり方 | 応用先・社会課題・仕事。特定学部からの就職を保証しない |
| 根拠資料 | URL、発行主体、参照箇所、根拠の要約、対象年度、確認日 |

関係そのものにも、両端の項目、種類、短い理由、根拠資料、事実か編集上の解釈か、条件、適用年度、公開・要確認の状態を持たせる。

同じ対象を扱うこと、方法を共有すること、進学・参加の資格があることを区別する。複数の項目が関連していても、条件を確認せずに一連の実行可能な進路としてまとめない。

学校外の活動で学びを補う案も示せるようにする。ただし学校との両立が可能かは、時間・対象年齢・所属などの条件を確認する。「関連がある」と「組み合わせて実行できる」は別の判断である。

### 初期版で必要な情報整備の機能

利用者向け画面だけでなく、以下の管理と検査を初期版の必須要件とする。管理画面は必須ではなく、構造化ファイルと検査手順でもよい。

| ID | 要件 | 検査すること |
| --- | --- | --- |
| K01 | 対象領域の調査設計 | 問い・方法・学ぶ場所の確認表を作り、学校数だけで調査を終えない |
| K02 | 内容の抽出 | 見出しや検索結果だけでなく、元資料を確認して内容と条件を整理 |
| K03 | 関係の根拠管理 | 公開する接続に理由と参照箇所があり、解釈と直接の記載を区別 |
| K04 | 同義語と実体の整理 | 別名・同名・学校と学科の所属を確認し、重複や誤結合を防ぐ |
| K05 | 年度・募集状態の管理 | 過去の開催実績と現在の募集を分け、条件変更時に関係も再確認 |
| K06 | 未調査と偏りの把握 | 主要分野・隣接分野・校内外の機会の空白を記録。空白を推測で埋めない |
| K07 | 訂正・更新 | 資料変更・リンク切れ・矛盾が、どの説明と接続に影響するか把握 |
| K08 | 公開前検査 | 参照先の存在、関係種別、出典、必須項目を検査。未確認の資格関係は公開しない |

### 構築方式の比較

| 案 | 利点 | 主な弱点 | 判断 |
| --- | --- | --- | --- |
| URLとタグのカタログ | 小さく始めやすい | 内容の違い・横断関係を表しにくい | 中核にはしない |
| 利用時に検索してAIが地図を生成 | 新しい資料を探せる | 待ち時間と関係の誤生成が理解を妨げる | 初期表示には採用しない |
| 内容と関係を事前整理し、必要時に追加調査 | 根拠を確認した接続を速く表示できる | 編集と更新の作業が必要 | 採用案 |

専用のグラフDBを入れることと、関係を構造化することは別である。初期の技術選定はデータ量と既存環境を確認して行う。AIは抽出・関係候補の下書きに使えるが、初期版では人が根拠を確認して公開する。

## 地図の見せ方

### ワイヤーフレームで優先する視覚構造

Wireframe 03では、学問の枝を開くと「今、触れてみる（イベント・公開講座）」「続けて取り組む（校内部活動・学外活動）」「進学して学ぶ（高校・大学）」が展開する。学問の樹形図と近領域の表示を残したまま、具体的な機会を選べる。部活と所属校、講座と主催大学は双方向にたどり、対応する候補を強調する。機会の仮置き・相談カードにも対応する。掲載内容は架空の例であり、参加資格や入学経路の実証ではない。

ユーザー指定により、元の樹形図とそこから派生する近い領域の可視化を中心にする。カードの横並びだけに置き換えない。

- 興味を根として、問い、学問、取り組み方へ実線で枝分かれさせる。
- 選択中の枝を強調し、その枝から近い領域へは点線と関係の説明でつなぐ。
- 近い領域への移動時にも、元の枝を消したり別の学問に差し替えたりしない。
- 隣接領域は淡いまとまりの中に配置し、階層関係と横断的な関連を形でも区別する。
- 狭い画面では図の領域内を横に動かせるようにし、ページ全体は横にはみ出させない。文字を極端に縮小しない。
- 線は進学保証や必須順序ではなく、興味と内容の関係を示す。

地図には同じ内容を共有する2つの見方を用意する。

- 「学びを知る」：領域の意味・違い・重なりを見渡す。初期表示の中心。
- 「学べる・試せる場所」：選択中の領域に関連する具体的な学校や活動を見る。

領域を選んだ状態のまま切り替えられ、毎回検索し直す必要はない。いずれの見方からも詳細や外部情報へ進める。

具体的な機会を見る画面は、自由配置の巨大なグラフではなく、見出しのある3つのまとまりとする。これを領域全体の分類に代用しない。

| まとまり | 見せるもの |
| --- | --- |
| 今、試せること | 学外活動、公開講座、オンラインで見られる紹介など |
| 高校でできること | 学校・学科、その学校に属する授業や校内活動 |
| その先の学び | 大学・学問、さらに調べるための入口 |

- PCでは横方向、狭い画面では縦方向に配置する。小さい文字の地図全体を縮小表示しない。
- 見出しの並びはすべてを順番に通る必須ルートを意味しない。どこからでも開ける。
- 校内活動は学校との所属関係を見せ、誰でも参加できる学外活動と区別する。
- 初期表示は各まとまり2〜3件を目安とする。数はプロトタイプで理解度を確認して調整する。
- 通常は線を最小限にし、選んだ候補に関係する接続だけ強調する。
- 接続には「関連する学問」「この学校の活動」「進学条件を確認」など意味を付ける。接続の存在を進学保証にしない。
- 候補カードに出すのは名前・何ができるかの一文・必要最小限の条件。詳細説明をカードに詰め込まない。
- 色に加えて見出し・ラベル・配置で分類する。キーボードや読み上げでたどれる一覧構造を持たせる。

## 内容を理解し、外部情報へ進む詳細シート

候補を選ぶと主画面上のシートを開く。別の深い階層へは進ませない。

領域のシートはR2の説明とR3の接続を持つ。学校・活動など具体的な候補のシートに置く情報：

1. 名前と、この候補でできることの短い説明。具体的な内容は必要に応じて展開できる。
2. 選んだ興味との関係。
3. 判断の前提になる条件。学校なら場所や学科、活動なら対象年齢・費用・日程・募集状況など。
4. 目的がわかる外部リンクを1〜3件。
5. 任意の「気になる」。一言メモは展開してから記入する。

リンクの見せ方の例：

| リンクの目的 | ラベル例 | 添える情報 |
| --- | --- | --- |
| 学校で学べる内容 | 授業・実習を見る | 提供元名、公式サイト |
| 校内活動 | 部活の活動内容を見る | 提供元名、公式サイト |
| 学外活動の参加可否 | 対象年齢・開催日を確認 | 主催者名、募集案内 |
| 大学での学び | 研究テーマを見る | 大学名、学科紹介 |
| 詳細な募集要項 | 出願条件を確認 | 提供元名、PDF、対象年度 |

実在のリンクを登録する際に、遷移先がラベルに合う内容を持つことを確認する。上記はUIの文言例であり、リンク先の存在を確認した一覧ではない。

「詳しくはこちら」だけにせず、何がわかるかを伝える。可能なら公式トップページより、目的のページに直接つなぐ。HTML・PDF・動画など形式も必要に応じて示す。

## アプリ内と外部の役割分担

| シンボクに持つ | 外部へつなぐ |
| --- | --- |
| 領域の対象・問い・方法・学ぶ内容 | 授業・研究についてさらに詳しく読む原文 |
| 領域同士の共通点・違い・関係の理由 | 学校・主催者の写真や紹介動画 |
| 代表例と、同じ観点での比較 | 専門的な解説や個別事例の全容 |
| 対象・場所など、入口で必要な条件 | 最新の募集要項や申込手続き |
| 情報源と確認日 | 公式の問い合わせ・予約 |
| 本人が選んで残した候補と一言 | 情報提供元の詳細ページ |

「意味を理解する」「違いと重なりを把握する」「次に何を見るか」はアプリが担う。網羅性は内容の整理と接続で確保し、公式情報の全文複製や専門教材のすべてを抱えることで実現しようとしない。

掲載した条件にも更新が必要。未確認情報を補完せず、確認日・対象年度・公式での確認先を示す。リンク切れ時は提供元トップなど確認済みの別の入口を明示し、無言で置き換えない。

## 外へ出て、戻れる

- 外部リンクは通常のリンクとして提供し、標準操作で別タブに開く。新しいタブで開くことがわかるラベルを添える。
- 元のタブでは選択中の興味・候補・スクロール位置・開いているシートを維持する。
- 別タブを使えない環境では、ブラウザの戻る操作でどこまで復元できるかを実装後に確認する。未検証の復元を保証しない。
- 戻った際にアンケートや記録画面を自動で開かない。
- 必要な人だけ「気になる」を押すか、一言メモを開く。
- 外部サイトの閲覧内容を読み取らない。リンクを押したことを「読了」「参加」「理解した」と扱わない。

## 開く手間と戻る手間を減らす

- インストール不要のWebアプリを想定する。
- 初回から地図を表示し、必須入力はゼロにする。
- 目標は「候補を開く → 目的のリンクを選ぶ」の2操作で外部情報に着くこと。全候補・全環境で達成済みという主張ではない。
- 初期の地図表示をAI応答待ちにしない。小さな確認済みデータを使う。
- 継続利用したい本人だけが「この端末に残す」を選ぶ。初期状態で個人記録を永続保存しない。
- 保存を選んだ場合、次回は残した候補から再開できる。共用ブラウザから見える可能性を説明し、削除を用意する。
- 個人の興味・メモをURLへ埋め込み、履歴や外部への遷移で意図せず露出させない。

## 次に試作で検証すること

実装上の主要な負荷は、描画だけでなく、内容の編集・関係の検証・更新にもある。対象地域・分野・実在候補数を絞っても、関係の根拠と異なる関わり方の提示は削らない。

情報整備後には、次の反例でも接続の妥当性を点検する。

- 名前に「海」がなくても、内容が裏づける関連を拾える。
- 名前に「海」があっても、問いや方法が違えばその違いを説明できる。
- 活動への参加経験を、大学の出願資格や優遇と混同しない。
- 未掲載の学校・活動を存在しないものとして扱わない。
- 関連があるだけで、年齢・所属条件に合わない活動を参加可能と表示しない。

本人の利用では、以下を確認する。

1. 初見で「何が見られるアプリか」を説明できるか。
2. チュートリアルなしで気になる候補に触れられるか。
3. リンクを開く前に、遷移先で何がわかるか予想できるか。
4. 外部から戻って、続きの候補を迷わず開けるか。
5. マップの線を進学保証や必須の順路だと誤解しないか。
6. 外部に出る前に、選んだ領域が何を扱い、何をする領域か説明できるか。
7. 近い2領域の共通点と違いを1つずつ把握できるか。
8. 別の領域へのつながりが、単なる線ではなく理由として理解できるか。
9. 学校や活動が、その領域とどう関係するか説明できるか。
10. 調べたことで選択肢の違いが理解できるか。クリック数だけを成功指標にしない。

これらは検証計画であり、実機や本人による検証は未実施。

## 保護者から情報を添える動線

本人の探索を起点に、情報提供を会話につなぐ。保護者用の閲覧入口は本人の地図とは分ける。

1. 本人：入口 → 地図 → 気になるもの → 候補ごとの公開範囲。初期値は「自分だけ」。
2. 本人：「保護者に共有」を選ぶ。自分用メモは共有対象に含めない。
3. 保護者：招待された共有スペース → 本人が公開した候補 → 関連する候補を選ぶ → URL／写真・見出し・種類・領域タグ・ひとことを添える。
4. 本人：受け取り箱 → 内容を確認 → 気になるに残す／今は見送る。見送った情報は戻せる。
5. 探索中：タグが一致する学問の詳細に「この領域に届いたおすすめ」として表示する。学問同士の関係線には混ぜず、投稿者のタグによる関連だと明示する。

おすすめは第三者からの情報であり、アプリが検証した進学情報と区別する。URLの本文理解や画像OCRを実装するまでは、送信者が書いた見出し・タグでのみ接続する。受信者の既読・採否・私的メモを保護者向けに出さない。共有を取り消すとその候補は共有画面から外れる。

### 今回の操作モック

同一ブラウザの「保護者側の表示を試す」で操作を切り替える。認証された別ユーザーへの共有ではない。URL／写真の入力、タグ、公開範囲、受信箱、採否、領域詳細への表示、任意の端末保存まで動作する。写真はブラウザで縮小し、外部にはアップロードしない。

### 実際の複数人利用に必要な実装

- 本人と保護者のアカウント、期限・失効のある招待、明示的な関係承認。全インターネット公開は初期機能にしない。
- 公開範囲は「自分だけ／接続した相手を選択」。このモックの「保護者」は将来の相手単位アクセス権に置き換える。
- サーバー側で閲覧者と所有者・共有相手を毎回照合する。非公開データを保護者のクライアントへ送らない。プレビューはアクセス制御の代わりにはならない。
- 共有取消、相手の解除、写真の削除とアクセス失効。既に保存された画像まで消せるとは表示しない。
- 投稿されたURL／画像の保存、ファイル検査・非公開配信、文字認識・内容の要約は別工程とし、本人が原文を確かめられるようにする。
- 本人が受信を止める機能、投稿数制限、受信通知設定。送信済みの表示と本人の採否を分離する。
